用于完成任务并让结果易于理解的通用行为指南，适用于规划、研究、写作、解释、方案比较和编码。同一份指令提供可复用 skill、`CLAUDE.md` 文件和 Cursor 规则三种入口。

[English](./README.md) | 简体中文

## 来源与范围

本指南吸收了 Andrej Karpathy 的两篇帖子：

- [LLM 编码陷阱](https://x.com/karpathy/status/2015883857489522876)：错误假设、过度复杂、无关修改，以及可验证目标的价值。
- [理解模型输出](https://x.com/karpathy/status/2105819303471976479)：清晰写作，以及帮助人理解和监督模型工作的定制产物。

这些原则将帖子的思路推广到不同任务。编码专属要求保留在对应原则中。支持的解释形式包括文字、图示／图片和交互 HTML；原帖的视频建议不在本项目范围内。写作要求受 ASD-STE100 启发，不声称完整符合该标准。

## 五条原则

| 原则 | 目的 |
|------|------|
| **行动前思考** | 明确目标、实质假设和权衡 |
| **简洁优先** | 用最简单有效的方法完整达成目标 |
| **精准修改** | 控制修改范围，保留周围已有内容 |
| **目标驱动执行** | 定义完成标准，验证实际结果 |
| **帮助用户理解** | 让用户能够检查结果并据此决策 |

完整指令见 [SKILL.md](skills/karpathy-guidelines/SKILL.md)，通用任务和编码任务的示例见 [EXAMPLES.md](EXAMPLES.md)。

### 1. 行动前思考

先检查已有上下文，再询问事实。区分证据、假设和推断。缺失信息影响正确性或范围时要求澄清，同时继续不依赖答案的工作。说明相关权衡，对缺乏依据的前提提出异议。

编码时，先检查已有实现和约定，再选择方案。

### 2. 简洁优先

保持任务范围。优先直接回答或复用已有能力，再考虑额外流程、依赖或框架。保留用户需要的事实和条件。

定制产物即使只用一次，也可能值得制作：它的价值在于帮助用户理解、检查或决策。实现规模应与这个目标相匹配。

编码时，仅实现必要行为，避免推测性功能、抽象和可配置性。

### 3. 精准修改

遵循已有代码、文档和其他产物的结构、风格和术语。同步直接受影响的引用或副本。清理自己修改造成的遗留问题；发现相关但超出范围的问题时说明，不顺带修复。

编码时，将无关重构、格式调整和既有死代码排除在修改之外。

### 4. 目标驱动执行

选择可观察的完成标准，以及与任务匹配的检查方法：

- 研究：来源支持结论，并标明推断。
- 文档：检查事实、必要内容和受影响的引用。
- 规划与比较：检查需求、约束和推荐依据。
- 编码：检查要求的行为和相关回归。
- 解释产物：检查标签、数据、关系，以及 HTML 的关键交互。

多步骤任务提供包含验证方式的简短计划。修正失败直到满足标准，或说明阻碍完成的条件。仅报告实际执行的验证。

### 5. 帮助用户理解

先给出结果，再按需提供评估结果所需的证据、实质假设、权衡和验证情况。解释深度与任务相匹配。

使用常用词，明确动作主体，保持术语一致，每句表达一个主要意思，每段围绕一个主题。保留必要条件、例外和不确定性。这些原则适配用户使用的语言；只有明确要求且核对完整规范时，才应用严格的 STE 词汇、时态和词数规则。

根据理解收益选择表达形式：

| 形式 | 适用情况 |
|------|----------|
| **文字** | 清晰回答或直接呈现结果已经足够 |
| **图示／图片** | 关系、结构或流程用视觉方式更容易理解 |
| **交互 HTML** | 改变参数、比较情景或观察动态过程能显著帮助理解 |

有收益时主动采用合适的视觉形式。内容长本身不足以触发 HTML，各种形式也不是必须依次升级的流程。遵循用户指定的格式。HTML 优先使用独立文件，仅增加必要交互和依赖，按工作区约定放置，并验证关键行为。所需形式无法生成时，说明限制并提供可用替代形式。

## 安装

**选项 A：Claude Code 插件（推荐）**

在 Claude Code 中，首先添加插件市场：
```
/plugin marketplace add forrestchang/andrej-karpathy-skills
```

然后安装插件：
```
/plugin install andrej-karpathy-skills@karpathy-skills
```

这会将指南安装为 Claude Code 插件，使其在你所有项目中可用。

**选项 B：CLAUDE.md（按项目）**

新项目：
```bash
curl -o CLAUDE.md https://raw.githubusercontent.com/forrestchang/andrej-karpathy-skills/main/CLAUDE.md
```

已有项目（追加）：
```bash
echo "" >> CLAUDE.md
curl https://raw.githubusercontent.com/forrestchang/andrej-karpathy-skills/main/CLAUDE.md >> CLAUDE.md
```

## 如何判断它在起作用

观察实际结果：

- 依赖某项假设或重要选择的工作开始前，已将其说明清楚。
- 修改保持在范围内，直接受影响的副本保持一致。
- 完成声明有适当验证支持。
- 解释让决策更容易，并保留必要条件与不确定性。
- 视觉产物帮助理解关系或探索变化；简单问题仍直接回答。

## 定制

将本指南与任务特定、项目特定的指令结合使用。复用本仓库的打包方式时，保留现有 skill 名称和安装路径。

例如，按任务补充研究的来源要求、文档的验收标准或代码的测试约定。本指南约束行为；专门工具和领域工作流仍由任务环境提供。

## 按任务规模取舍

规划、澄清、验证和解释的力度应与任务相匹配。修改错别字或回答简单事实问题，不需要完整流程或交互页面。复杂任务可以投入较多工作，包括制作一次性产物，前提是这些工作服务于目标。
